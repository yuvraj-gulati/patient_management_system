# Patient Management System

A full-stack patient management web application built with Angular and ASP.NET Core. The project includes user registration, login, OTP verification, patient management, organization management, profile display, and dashboard charts.

## Tech Stack

- Angular 16
- TypeScript
- ASP.NET Core Web API (.NET 8)
- Entity Framework Core
- SQL Server
- Bootstrap
- Chart.js

## Features

- User registration and login
- Demo OTP verification flow
- Patient record management
- Organization record management
- Dashboard with charts
- Profile and phone number formatting
- Excel import/export support for patient data
- Layered backend structure using controllers, services, repositories, DTOs, and EF Core

## Project Structure

```text
Frontend/
  src/app/auth                  Authentication pages
  src/app/patient-management    Patient management screens
  src/app/organization-management
  src/app/patient               Dashboard and charts
  src/app/shared                Header, sidebar, profile, pipes

Backend/
  Backend                       API controllers and startup configuration
  Backend.Domain                Entities, DbContext, repositories, migrations
  Backend.Service               Business logic layer
  Backend.Shared                DTOs and shared models
```

## Getting Started

### Prerequisites

- Node.js
- Angular CLI
- .NET 8 SDK
- SQL Server or SQL Server Express

### Frontend Setup

```bash
cd Frontend
npm install
npm start
```

The Angular app runs at:

```text
http://localhost:4200
```

### Backend Setup

Update the database connection string in:

```text
Backend/Backend/appsettings.json
```

Example for local SQL Server Express:

```json
"ConnectionStrings": {
  "DefaultConnection": "Server=localhost\\SQLEXPRESS;Database=PatientManagementDb;Integrated Security=True;TrustServerCertificate=True;MultipleActiveResultSets=true;"
}
```

Then run:

```bash
cd Backend/Backend
dotnet restore
dotnet ef database update
dotnet run
```

The backend API runs with Swagger enabled in development mode.

## Demo Login Flow

The current OTP flow is a demo implementation. After login, the app navigates to the OTP page, where the hardcoded OTP is:

```text
123456
```

In a production version, the OTP should be generated by the backend and sent through an SMS or email provider.

## Build Commands

Frontend:

```bash
cd Frontend
npm run build
```

Backend:

```bash
dotnet build Backend/Backend/Group8Backend.sln
```

## Notes

- Build output folders such as `bin/` and `obj/` are ignored and should not be committed.
- The database itself is not uploaded to GitHub. It should be created locally using Entity Framework migrations.
- The connection string should be changed for each developer's local SQL Server setup.
